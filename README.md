## Reflection Answers

1. **How GitLens' blame view helps understand changes**:
   GitLens displays inline change authorship at the end of each line as soon as you place your cursor on it. Hovering over the blame annotation reveals the exact commit hash, author, timestamp, and commit message. This eliminates guesswork in collaborative codebases, allowing team members to immediately identify who wrote a specific function and the historical context behind the change.

2. **Live Share pair programming — Advantage vs. Limitation**:
   - *Advantage*: Enables true real-time remote collaboration with synchronized cursor tracking, independent scrolling, and a shared terminal session without needing to screen-share or pass code files back and forth.
   - *Limitation*: Unlike sitting next to a partner in person, non-verbal cues and informal whiteboarding discussions require extra verbal communication; network fluctuations can also momentarily disrupt the shared session state.

3. **Why employers value collaborative commits in a portfolio repository**:
   Modern engineering is almost entirely team-based. Employers look for developers who understand git hygiene, branch workflows, peer code reviews, clear commit attribution, and pair programming tools. A commit history with clear co-authorship and descriptive messages demonstrates strong teamwork, version control maturity, and professional communication skills.
